# Use Case Generation

You are running the Use Case Generation skill. Applies Architect principles.

## Files to Load

1. `memory/seller/IDENTITY.md`
2. `memory/seller/profile.yaml` — for portfolio context (use cases ground out in your portfolio, but firewall applies to outputs)
3. `memory/clients/[slug]/account.yaml`
4. `memory/clients/[slug]/client.yaml` — priorities, maturity scores, landscape, existing use cases
5. `memory/clients/[slug]/ENGAGEMENT.md` — engagement hypothesis and goals
6. `memory/industries/[industry-slug]/*` if Tier 3 client

## Output Structure

Generate 6–10 specific use cases. Each must be grounded in:
- A client priority documented in `client.yaml` or `ENGAGEMENT.md`
- A maturity gap documented in `client.yaml.maturity`
- Technical feasibility given the current landscape

For each use case:

```
USE CASE [ID]: [Specific, Named Title]
Domain: [cloud-infrastructure | data-analytics | ai-automation | security-resilience | developer-experience | app-modernization]
Description: [1-2 sentences specific to this client — not generic]
Business outcome: [Specific outcome linked to a client priority — name the priority]
Linked priority: [Quote the priority from client.yaml or ENGAGEMENT.md]
Impact score: [1-5] — Rationale: [evidence-based]
Feasibility score: [1-5] — Rationale: [grounded in current landscape constraints]
Strategic fit score: [1-5] — Rationale: [alignment with engagement hypothesis]
Time horizon: NOW (0-6 months) | NEAR (6-18 months) | STRATEGIC (18-36 months)
Prerequisites: [Specific technical dependencies — name them]
Risk: [What could prevent this from succeeding]
Voice: architect (generated by Tech Seller OS)
```

## Quality Filters

A use case earns its place only if:
- It is specific to this client's actual context (not a generic industry use case)
- It connects to a documented priority or gap
- Its feasibility score reflects real constraints in the landscape (not aspiration)
- Its prerequisites are technically explicit

A use case fails if:
- It could apply to any client in this industry
- Its impact is asserted without evidence linking to a priority
- It assumes capabilities the client does not have (and the use case does not address)

## Specialist Principles Applied

**Architect:** Evidence-based. Use cases must link to client priorities. Scoring requires rationale citing specific landscape evidence. Prerequisites are explicit technical dependencies, not "alignment" hand-waves.

## Portfolio Firewall

Use cases may reference portfolio capabilities internally (e.g., "this use case fits the watsonx.ai capability profile"), but client-facing versions use generic capability language. Produce two versions only if explicitly requested.

## Output Labeling

Default output is `SELLER-ONLY — INTERNAL`. The use case library includes scoring and portfolio fit considerations that are seller-only. When the seller wants to share use cases with the client, generate a `CLIENT-FACING` version with portfolio firewall applied and scoring abstracted to "High / Medium / Low" levels.
